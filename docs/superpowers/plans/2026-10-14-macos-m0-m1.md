# macOS port, M0 + M1: build split, platform seam, rooted window

**Branch:** `plan/macos-m0-m1` (plan only, off master `a1fa1df6`). Input:
`target/macos-inventory.md` (gitignored scoping notes). This plan needs a codex
review before code moves.

**Goal (M0):** the workspace builds and its non-GPU tests pass on macOS. Linux
behaves exactly as it does today. The KMS device layer sits behind a platform
trait, so the X drawing half of `KmsBackend` compiles without DRM.
**Goal (M1):** on macOS, one native window shows the whole X screen
(Xephyr-like). Core drawing, RENDER text and Present Copy are visible from
`xterm`, `xeyes` and `twm`. There is no input yet.

**Non-goals (M2+):** input and keyboard mapping (M2). Live resize, a HiDPI
scaling policy, clipboard and font-path polish (M3). Rootless and GLX (M4).
Windows. Removing the dead host-X11 code (separate cleanup, see decision 9).

Tags: **[C]** = checked in code at `a1fa1df6` (file:line). **[A]** =
assumption about macOS, AppKit or KosmicKrisp that must be verified on eiger
(M2 MBP) before the task that depends on it is merged.

## Decisions

### 1. The crate layout stays as it is; the portable half becomes generic in `yserver`

`KmsBackend` becomes `XBackend<P: Platform>`, still in the `yserver` crate, with
`pub(crate) type KmsBackend = XBackend<PlatformBackend>`. New code:

| path | role | built on |
|---|---|---|
| `kms/render/backend/seam.rs` | the `Platform` trait | all targets |
| `src/surface/` | `SurfacePlatform`: OS-neutral Vulkan swapchain platform, one swapchain per surface | all targets (`cfg(any(target_os="macos", test))`) |
| `src/macos/` | AppKit shell: NSApplication, NSWindow, CAMetalLayer, display link, launch | `cfg(target_os="macos")` |

`build.rs` emits one cfg alias, `kms`, for `any(linux, freebsd)`, declared in
`check-cfg`. The DRM modules are gated with `#[cfg(kms)]` at the module line
only.

**Why not the inventory's `yserver-x` + `yserver-macos` crates:**
- Rust allows inherent impls only in the crate that defines the type. If
  `XBackend` moved to `yserver-x`, the 11.8k lines of `kms/*` (written as
  `impl KmsBackend { … self.core … self.platform … }`) could not stay as they
  are.
- The orphan rule also forbids `impl Backend for XBackend<KmsThing>` outside
  `yserver-x`.
- The alternatives are both bad: rewriting `kms/*` into trait-method bodies or
  free functions over `&mut XBackend<Self>`, or moving DRM code into
  `yserver-x`, which defeats the split. Either is the large `PlatformBackend`
  churn that risk 1 warns about.
- Staying in one crate also avoids 3a/3b-style `pub` widening.
- Compile time on Linux is unchanged: `macos/` is cfg'd out and `surface/` is
  test-only there.
- The crate split stays possible later, once the hook list has settled
  (decision 2).

**Why not a cfg type alias (`type Platform = …` per target, no trait):**
- Linux CI would never type-check the macOS side.
- There would be no written contract between the two platforms.
- `trait_impl.rs` would need per-method cfgs for DRI3.

With the generic, the portable half is compiled against a second platform
(`SurfacePlatform`) on every Linux CI run.

**Speed:**
- Static dispatch: `P` is monomorphised, and the accessors are `#[inline]`
  field reads. KMS codegen is identical in principle; acceptance checks
  release size and lavapipe timings within noise.
- `OutputSink` stays `&mut dyn`, as decided in 3b. It is used once per tick,
  not on a paint path.
- Cost: test builds instantiate the portable half twice. Measure it (task
  M0.7).

### 2. The `Platform` trait: narrow accessors plus a hook table

- **What crosses the trait:** only render or `yserver-core` types
  (`GpuCore`, `OutputLayout`, `PresentCaps`, `PresentClockSample`, `vk::*`).
  No DRM, GBM or AppKit type crosses it (maintainer decision 1).
- **Size:** about 7 accessors and 55 hooks. About 30 hooks have defaults, so
  `SurfacePlatform` overrides about 25.
- **Why hooks are associated functions taking `&mut XBackend<Self>`:**
  `kms/*` keeps its `impl XBackend<PlatformBackend>` methods unchanged, and
  each hook forwards to the existing `backend_<module>_<name>`.
- **What stays outside the trait:**
  - The portable `Backend` methods (draw/render/windows/…) are implemented
    once in `impl<P: Platform> Backend for XBackend<P>`.
  - The KMS-only state (the ~38 fields) moves to
    `XBackend.pstate: P::BackendState`. For KMS that is `KmsBackendState`;
    for the surface platform it is `SurfaceBackendState`.
  - The rename is mechanical: `self.<field>` → `self.pstate.<field>`, about
    376 sites, in one commit.
- **CI naming constraint:** the layout grep forbids `platform::` in
  `portable/`, so the trait lives in `backend/seam.rs` and is imported as
  `seam::Platform`.

### 3. Portable logic now in `kms/*` moves into `portable/` before the cfg split

If this logic stayed in `kms/*`, `SurfacePlatform` would have to re-implement
it. The moves:
- `kms/cursor.rs` → `portable/cursor.rs`. It has no DRM. Its two plane calls
  go through `cursor_plane_mut()`, which `OutputSink` already provides.
- The COW overlay functions: `get/release_overlay_window` and `cow_host_xid`,
  from `kms/scanout.rs`. The direct-scanout coupling goes through
  `direct_scanout_owns_frame`.
- The scene readback path of `kms/readback.rs`.
- The fd-free half of `kms/present.rs` → `portable/present.rs`:
  - batch registration, completion drain, retained wakes;
  - source pins (`pin/release_present_source`, `note_present_pixmap`);
  - `enqueue_present_completion` and `signal_present_wake`.

  Two things stay in `kms/present.rs` behind hooks: fd registration
  (`register_present_batch_wait`) and the vblank/clock code.

`maybe_composite` is split into a portable `compose_tick()` (frame close,
engine flushes, `scene.tick`, telemetry). The KMS hook keeps the
direct-scanout and atomic-cursor logic around it.

### 4. Capabilities, not cfg, decide behaviour

The rule: `target_os` appears only in `Cargo.toml`, the `build.rs` alias,
module declarations, the two core shims, the signal thread and the launch
entry. All behaviour differences come from:
- a hook,
- a `VkContext` flag (decision 5), or
- a `BackendCapabilities` field.

### 5. Render crate gates (OS-neutral, by extension presence)

- **Instance extensions:** a wanted list filtered by
  `enumerate_instance_extension_properties`. It always includes
  `debug_utils` if present. Callers can add `VK_KHR_surface` plus one
  platform surface extension (`VK_EXT_metal_surface`, or
  `VK_EXT_headless_surface` for tests). This replaces
  `required_instance_extensions`.
- **Device:** request `VK_KHR_swapchain` when the context is created with
  `wants_present = true`, and fail creation if it is missing. The device pick
  also requires `vkGetPhysicalDeviceSurfaceSupportKHR` for the graphics
  queue. The "unverified generic fallback" warning (`device.rs:1317`) becomes
  `info` when there is no DRM device to match.
- **New flag `dmabuf_export`** (`external_memory_fd` ∧
  `external_memory_dma_buf`):
  - `allocate_exportable` and `linear_tiling_exportable` return `Unsupported`
    without it;
  - `supports_dmabuf_export` follows the flag (which also turns off GLX-TFP);
  - the startup export probe (`backend/kms/export.rs:60`) stays KMS-side.
- **`create_present_completion_signal` without `supports_sync_fd()`:**
  create a plain semaphore and go straight to `PresentBatchWait::Poll`, with
  no per-frame warning (`frame.rs:894–903`).
- **`device.rs` missing-extension warns:** "Vulkan-fed scanout will not work"
  is logged only when a KMS consumer asked for those extensions (a
  `wants_kms_interop` flag).

### 6. Threading (M1)

- **Main thread (AppKit):**
  - creates `NSApplication`, one `NSWindow` (not resizable in M1) and an
    `NSView` backed by a `CAMetalLayer`, then runs `[NSApp run]`;
  - handles `applicationShouldTerminate` (returns `TerminateLater`), window
    close and the occlusion notification;
  - runs `UiCommand`s (`Quit`, `SetTitle`; `SetCursor` in M2) that arrive via
    `dispatch_async` to the main queue;
  - never touches Vulkan.
- **Core thread (spawned by main after the window exists):**
  - receives `NativeSurface::Metal { layer: NonNull<c_void> }`, an
    OS-neutral enum with a `Send` newtype. The layer is retained by main
    until the shutdown handshake ends [A: KosmicKrisp WSI calls on
    CAMetalLayer are safe off the main thread];
  - builds `VkContext`, `SurfacePlatform`, `XBackend`, the listeners, then
    calls `run_core`;
  - owns every Vulkan object.
- **Display-link thread:** CVDisplayLink, or CADisplayLink on macOS 14+ [A:
  which one works for a window on eiger]. On each tick it calls
  `FrameClock::tick(host_time)`, which:
  - increments the surface MSC and stores UST as two atomics;
  - posts a wake only if the core armed one: a frame awaiting retirement or a
    Present vblank target.

  An idle desktop therefore wakes the core 0 times per refresh.
- **Signal thread:** the FreeBSD `EVFILT_SIGNAL` kqueue thread
  (`lib.rs:1116`) is enabled for macOS too.
- **Platform → core wake:** a new `Message::PlatformEvent` (no payload)
  dispatched to a new `Backend::on_platform_event(state)`. The default is a
  no-op, so Linux is unchanged. Payloads (frame retired, occluded/visible,
  close) go in a platform-internal channel. An `AtomicBool` coalesces wakes.

  A message is used, not a pipe in `poll_fds`, because `RawFd` registration
  is Unix-only and the Windows port would need a different path. The
  existing `CoreSender` + mio `Waker` works on every OS.
- **Shutdown:** Cmd-Q, window close or SIGTERM → `Message::Shutdown` →
  `run_core` returns → the core thread destroys swapchain, surface and
  device → `UiCommand::Quit` → main replies to `TerminateLater` and releases
  the layer.

### 7. GLX off, DPMS off on the surface platform

- **GLX:** a new `ExtensionAvailability::Glx` reads
  `BackendCapabilities::glx_available`. The KMS backend returns `true`, so
  Linux advertises GLX as today, including no-render-node runs such as vng
  on lavapipe. GLX is not coupled to DRI3, because that would change Linux.
- **DPMS:** `dpms_capable` comes from the hook. KMS keeps `true`.

### 8. Presentation: offscreen slot images, copied into the swapchain at present

- **Slots:** `SurfacePlatform`'s `acquire_slot` hands out sink-owned
  offscreen images: 3 per surface, `COLOR_ATTACHMENT | TRANSFER_SRC`,
  B8G8R8A8_UNORM. They are not swapchain images. The swapchain is
  B8G8R8A8_UNORM, sRGB-nonlinear colour space, FIFO,
  `minImageCount = clamp(3)`, composite alpha OPAQUE, usage `TRANSFER_DST`.
- **`finish_frame`:**
  1. `vkAcquireNextImageKHR` with timeout 0;
  2. the scene's record closure;
  3. the target's `record_post_compose` records offscreen → swapchain copy
     and the transition to `PRESENT_SRC_KHR`;
  4. submit: wait = acquire semaphore (`renderer_wait_semaphore`), signal =
     binary render-done semaphore + a timeline value;
  5. `vkQueuePresentKHR`, waiting on render-done.
- **Why the copy:**
  - root `GetImage`/`CopyArea`/`dump_scanout` read the last frame; the
    measured swapchain usage does list `TRANSFER_SRC` (and `TRANSFER_DST`),
    so composing straight into swapchain images is possible later, but slot
    images keep the frame lifetime independent of acquire order;
  - buffer age (`last_present_generation`) stays exact, independent of
    swapchain image order;
  - the same per-surface slots work for rootless.

  The copy costs about 25 MB per composed frame at 3200×2000. That is
  negligible next to Apple memory bandwidth, and only damaged frames compose.
  Composing straight into swapchain images is a later optimisation, if
  `TRANSFER_SRC` turns out to be supported.
- **Retirement:** `on_page_flip_complete` fires on the first display-link
  tick after the frame's timeline value has signalled
  (`vkGetSemaphoreCounterValue`, non-blocking). It reports
  `FlipRetirement { clock: (msc, ust) }`.
- **In-flight limit:** the scene keeps at most one frame in flight per
  output, so with 3 or more images the acquire does not wait [A:
  KosmicKrisp's acquire with timeout 0 maps to a non-blocking
  `nextDrawable`, or returns `NOT_READY`].
- **Errors:** `NOT_READY`/`TIMEOUT` → `FinishOutcome` error →
  `recycle_failed_slot`, retried on the next tick. `OUT_OF_DATE`/`SUBOPTIMAL`
  → recreate the swapchain at the next tick; slot images are kept, since
  their size is the X output size.
- **Occlusion:** while the window is occluded the surface reports no slots,
  like `kms_outputs_active = false`, so the core never waits on a hidden
  layer [A: an occluded CAMetalLayer starves `nextDrawable`].
- **Per surface:** `output_idx` ↔ surface. Each surface has its own
  swapchain, slots, `FrameClock` and RandR CRTC. M1 creates exactly one
  surface showing root rect `(0,0,w,h)`. Rootless (M4) adds surfaces whose
  root rects are the top-levels. Nothing above the sink assumes one
  swapchain or the whole root.
- **Cursor:** `CursorPlaneSink::fits` returns `false`, so the scene paints a
  software cursor. The macOS arrow still shows over the window. M2 maps the X
  cursor to `NSCursor`.

### 9. Present clock, RandR, HiDPI, sockets, fonts (M1)

- **What Present clients see:**
  - Copy mode only: `PresentCaps` without flip, and `try_present_direct` is
    unhandled.
  - MSC = per-surface display-link tick count, starting at 0.
  - UST = display-link host time in µs, from `mach_absolute_time` timebase
    conversion.
  - `PresentClockSource::BackendVblank`.
  - `arm_idle_vblanks` and absolute targets arm the display-link wake.
  - Completions use the `Poll` path (1 ms re-check while one is pending).
- **Later improvement (not M1):** a completion waiter thread doing
  `vkWaitSemaphores` on the timeline value, posting `PlatformEvent`. Measured
  need first.
- **Calibrated timestamps:** not used in M1 [A: which time domain
  KosmicKrisp exposes].
- **RandR:** one synthetic output `WINDOW-0`, one CRTC and one mode =
  `--geometry` in pixels; refresh = the display link's nominal period
  (fallback 60). mm is derived at 96 DPI. Config requests are refused, as in
  the ynest compat design (`specs/2026-04-29-nested-randr-compat-design.md`).
  Gamma size 0. Resize is M3.
- **HiDPI:** the X screen is in backing-store pixels. `--geometry 1600x1000`
  means 1600×1000 X pixels, and the window is 1600/scale × 1000/scale
  points. `layer.contentsScale = backingScaleFactor` and
  `drawableSize = pixels`.

  Rationale: 1:1 pixels, no resampling, exact `GetImage`/readback
  semantics, and RandR and Present need no scale factor. The cost is small
  UI on Retina at 96 DPI, which is acceptable for a development milestone.
  The policy (physical DPI, `--scale` via the existing scale pass) is M3.

  If the window moves to a screen with a different scale, M1 keeps the pixel
  size and lets the window's point size change [A].
- **Socket:**
  - `/tmp/.X11-unix/X{n}` as today (`/tmp` → `/private/tmp`); `n` is
    auto-picked starting at 1.
  - `:0` is avoided because XQuartz's launchd agent may own it. The
    launchd-socket handoff is M3+.
  - The 104-byte `sun_path` limit is not reached with this path.
- **Fonts:**
  - `built-ins` always.
  - `default_font_path` (`kms/core.rs:729`) gains the existing-only
    candidates `/opt/X11/share/fonts/{misc,75dpi,100dpi,TTF,Type1}` and
    `/opt/homebrew/share/fonts`. This is OS-neutral because entries are
    filtered by existence [A: the code already filters].
  - Polish is M3.

### 10. Dead host-X11 code (decision 3 of the brief): leave it in M0/M1

`host_x11/` + `nested::run` total about 7.5k lines. They are unreachable, but
`HostKeyEvent` and `InputOrigin::NestedHost` live there and are used by the
KMS input path (`message.rs:254`). Removing them is a separate cleanup
branch: relocate the shared types, delete the module and `BackendFdKind::HostX11`.
It is independent of this plan and can go before or after.

### 11. Version

M0 and M1 merge to master with the workspace version unchanged (1.7.x).
Neither ships a macOS artefact. The 1.8.0 bump comes after M3 (input,
resize and scaling make the port usable).

## M0 tasks

**M0.1 yserver-core shims.**
- **Files:** `process_request/xshm.rs:665`, `unix_fd.rs:40`, `launch.rs:564`.
- **Steps:**
  - memfd → `cfg(any(linux, freebsd))`. Otherwise `shm_open` with an O_EXCL
    random name, `shm_unlink`, `ftruncate`, and `FD_CLOEXEC`.
  - `recvmsg` flags → `MSG_CMSG_CLOEXEC` on linux/freebsd. Otherwise flags

## Risks

1. **Seam size (M0.3–M0.5).** The `PlatformBackend` split touches the hottest
   code in the repo. Mitigation:
   - mechanical commits (field rename, accessor swap, alias, moves) are
     separate from logic commits;
   - test mapping and HW smoke on two machines before merge;
   - no behaviour change on KMS is permitted; any diff in
     `xdpyinfo`/lavapipe counts blocks.
2. **Trait shape churn.** The hook list mirrors today's `Backend` delegations
   and will move with M2–M4 (input hooks, NSCursor, resize, rootless
   surfaces). Accepted: the hooks are one-line forwards in KMS, and a crate
   split waits until the list stops moving.
3. **Present pacing.** Copy completions poll at 1 ms. FIFO latency is
   unknown on KosmicKrisp [A]. With no `present_wait`, retirement is
   approximate (tick after GPU done), so MSC is display-link time, not
   scanout time. Good enough for Copy clients, and measured in M1.3 before
   anything finer is built.
4. **KosmicKrisp WSI quirks [A]:**
   - acquire may block in `nextDrawable` despite timeout 0. Fallback: acquire
     on a small present thread;
   - surface or present calls may be main-thread-bound;
   - `OUT_OF_DATE` may not be reported on scale change;
   - the occluded layer may starve.

   Each gets its own eiger check in M1.2 before the dependent step merges.
5. **SysV shm on macOS.** `kern.sysv.shmmax` defaults to about 4 MiB [A], so
   MIT-SHM `Attach` of large images fails and Xlib falls back to PutImage
   (slow, but correct). `CreateSegment`/`AttachFd` (memfd shim) are not
   limited. M1 documents this; raising the sysctl is the user's choice. Tests
   that allocate more than 4 MiB SysV segments may fail on the macOS runner
   (M0.6 triage).
6. **CI coverage.** GitHub macOS runners may have no Metal device (see M0.6),
   so the Vulkan paths on macOS may be validated only on eiger/m4 by hand.
   macOS-only code (`src/macos/`) is compiled only on the macOS job.
7. **Test-build time** from the second monomorphisation (M0.7 bound).
8. **Dependencies:** `objc2` crate churn, and Homebrew paths differing on
   Intel (`/usr/local`). Intel Macs are out of scope; KosmicKrisp is
   aarch64.

## Implementation notes

- **M0.1 probe socket:** kept nix `socket` + nonblocking `connect`, flags set by `fcntl` (no `SOCK_*` flags).
  `std::os::unix::net::UnixStream::connect` blocks, which would bring back the backlogged-listener hang the
  probe guards against. The shm fallback is `yserver_core::anon_shm::create_anon_shm`; both fallbacks
  (`shm_open`, `set_cloexec`) are compiled and unit-tested on Linux.
- **M0.2 `wants_kms_interop`** gates *requesting* the five interop device extensions (dma-buf, sync-fd, DRM
  modifier, foreign queue), not just the warning. A surface context on Linux lavapipe therefore has no
  `dmabuf_export` and no SYNC_FD, like KosmicKrisp, so the Linux run exercises the macOS gates.
- **M0.2 surface support at device pick** is deferred to M1.2: `vkGetPhysicalDeviceSurfaceSupportKHR` needs a
  `VkSurfaceKHR`, which needs the instance that `VkContext::new_with_options` creates. The lavapipe test
  checks it on the created context instead. Instance extensions are filtered by presence for KMS too (a
  missing `debug_utils` no longer fails instance creation); `VK_KHR_portability_enumeration` is requested
  only without KMS interop, `VK_KHR_portability_subset` is enabled wherever advertised.
- **M0.2 gates:** `linear_tiling_exportable` needs no own gate (its only caller is `allocate_exportable`,
  gated first). The "generic fallback" warning is on the RenderEndpoint path only; automatic selection
  (the surface path) never logs it, so it is unchanged.
- **M0.3 field set:** 42 fields moved, not ~38: the plan's set plus `pending_present_source_waits` /
  `next_present_source_wait_id` (sync-file waits, KMS-only types) and `input_sender`. The fact "none in tests"
  was wrong: tests touch `pstate` fields (e.g. `scanout_m2`, `randr_id_alloc`), renamed mechanically too.
  `kms_outputs_active`, the Present batch/pin state and the cursor maps stay on `XBackend`.
- **M0.3 visibility:** `KmsBackend` is `pub` (integration tests name it), so `seam::Platform`,
  `PlatformBackend` and `KmsBackendState` are declared `pub` inside private modules (still unreachable from
  outside the crate) to satisfy the private-in-public rules. The plan's `pub(crate) type` would break
  `tests/glx_tfp_export.rs` and `tests/render_acceptance`.
- **M0.3 grep rule:** "portable names no `PlatformBackend`/`pstate.`" moves to M0.5. The remaining portable
  `pstate` sites (LEDs, drawable retire, `scanout_m2.active()` in the HW-cursor path) need `P::` hooks, which
  only exist once the portable impls are generic (review round 2, point 1). Release binary: +0.03%.
- **M0.4:** moved as planned (cursor, COW overlay, root reads, Present queue, `compose_tick` in
  `portable/compose.rs`). The root-read move also takes `read_root_scanout_assembled` and the CopyArea
  root fast path; their only KMS call is `read_on_screen_region` (later a hook). Sync-file readiness became
  `PresentBatchWait::signaled` (POSIX `poll`, render crate), so the queue needs no fd hook for it.
  `present_completion` (`PinnedWake`) is OS-neutral (core handle traits + `OwnedFd`) and stays unconditional
  rather than `#[cfg(kms)]`. `enqueue_present_completion` now skips the SYNC_FD export without device
  support, like the frame-close path from M0.2.
- **M0.5 hooks:** 80 `Backend` forwards plus 24 portable-side hooks (direct scanout, HW cursor plane,
  LEDs, Present poller/eventfd, on-screen read, COW release, export teardown) — more than the ~55 estimated,
  each a one-line KMS forward in `kms/platform_hooks.rs`. LED bits: portable passes the lit XKB indicators,
  the KMS hook maps them to `input::Led` (so `portable/` names no libinput type).
- **M0.5 GLX gate:** `ExtensionAvailability::Glx` reads `Backend::glx_available()` live (core default
  `true`, seam default `false`, KMS `true`), like the DRI3/RENDER/XKB gates next to it, instead of a
  `BackendCapabilities` snapshot. GLX requests sent without QueryExtension are not refused yet (same as DRI3).
- **M0.6 cfg split:** besides the listed modules, `present` (the old demo paint loop), `internal_probe`,
  `cursor_plane`, `outputs`, `export_holders`, `probe_executor` and the KMS backend tests/fixtures are
  `#[cfg(kms)]`; the integration-test crates are `#![cfg(kms)]` (they drive `KmsBackend`). `present_completion`
  stays unconditional (see M0.4). `surface/` is `cfg(any(not(kms), test))` rather than
  `cfg(any(target_os = "macos", test))`, so the non-KMS build can be emulated on Linux. Until the surface
  platform presents, the backend module carries `#[cfg_attr(not(kms), allow(dead_code))]` (portable code
  only KMS calls yet: cursor animation, pointer re-confinement, fresh root reads).
- **M0.6 headless runner** is `surface::headless::run` (OS-neutral); `macos::run` forwards to it. The signal
  thread is `spawn_signal_thread`, shared, with the FreeBSD kqueue path enabled for macOS. Headless screen is
  1600x1000; the socket/display logic is the unchanged `launch::resolve` (default `:7`).
- **M0.6 verification without a Mac:** no Apple target here. Instead the build was emulated on Linux with
  `cfg(kms)` off and `drm`/`gbm`/`input`/`udev` removed: `cargo clippy --all-targets [--features xdmcp] -D
  warnings` clean, `cargo test -p yserver --all-targets` green (178 passed), and the emulated
  `yserver :97 --headless` on lavapipe served `xdpyinfo` (1600x1000, RANDR/RENDER/Composite/Present, no GLX,
  no DRI3). Apple-only code (`libc` shm/fcntl shims, kqueue on macOS, Homebrew linking) is unverified.

- **M1.1 shell:** the window is created in `applicationDidFinishLaunching:`, which then spawns the core thread.
  `UiCommand` is a `ShellUi` trait (`set_title`, `quit`) whose macOS implementation dispatches to the main queue.
  The runner is `surface::server` (`run_headless`, `run_windowed`; was `surface::headless`). `--geometry` is parsed
  on every platform: KMS warns and ignores it, headless honours it. Cmd-Q needs a main menu, so the shell installs one
  with Quit.
- **M1.2 `NativeSurface`** is a struct (instance extension + surface-creating closure), not an enum with a `Metal`
  variant: layout rule 4 forbids `Metal` in `src/surface/`. The `VK_EXT_metal_surface` closure lives in
  `macos/window.rs`. Present support is checked at device pick (`VkContext::new_with_surface`): a probe surface is
  created on the new instance, used to filter candidates, and destroyed; the output then creates its own surface.
- **M1.2 frame sequence:** the copy into the swapchain is a second submit on the same queue, after the compose and
  after a non-blocking acquire. It is not part of the compose's `record_post_compose` with the acquire semaphore as
  `renderer_wait_semaphore`. Order: compose, acquire, copy, present. A failed acquire (`NOT_READY`, hidden window)
  therefore leaves the composed slot pending for the next tick, instead of stranding an acquired image and a
  signalled semaphore after a record error.
- **M1.2 slots:** 2 per surface, not 3. The scene keeps one frame pending per output and composes only when none is
  pending, so a third slot is never used (the rotation test showed `[0, 1, 0, 1]`). Slots are the render crate's
  offscreen compose target, made public as `scene::OffscreenTarget`. Retirement waits for a per-frame `VkFence`, not a
  timeline value: the device does not enable `timelineSemaphore`. Swapchain usage is `TRANSFER_DST` only, and
  `minImageCount` is `max(min, 3)` (lavapipe headless gives 4 images).
- **M1.2 tests:** lavapipe's `VK_EXT_headless_surface` drives real cycles (`surface::tests`). They check the order
  record → acquire → copy-submit → present → retire, slot rotation and buffer age, that the on-screen slot holds the
  composed pixels and equals a root read, the rebuild of an out-of-date swapchain, and a hidden window. Each was seen
  failing with presentation or retirement stubbed out. What the copy wrote into the swapchain image cannot be read on
  a headless surface; the tests count presented frames instead.
- **M1.3:** the display link is a `CVDisplayLink`, through our own CoreVideo declarations (not `objc2-core-video`),
  with a fixed-rate software ticker as fallback. `arm_idle_vblanks` and the completion arm both arm the clock's MSC
  target. Absolute vblank arming stays unsupported, so future-target Copy presents use the idle-display rung.
  `present_flip_in_flight` means a scene frame awaits retirement.
- **M1.4:** the `default_font_path` candidates gained `/opt/X11/share/fonts/{misc,TTF,Type1,100dpi,75dpi}` and
  `/opt/homebrew/share/fonts` (existence-filtered, so OS-neutral). The emulated non-KMS Linux build (as in M0.6)
  passes clippy with `-D warnings`. Nothing in `src/macos/` has been compiled yet: there is no Apple target here.
